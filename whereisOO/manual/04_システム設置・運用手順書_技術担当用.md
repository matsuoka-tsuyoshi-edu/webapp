# 【システム設置・運用手順書】Where is OO?（技術・管理者用）

> 本ドキュメントは、学校の情報担当教員、ICT支援員、ネットワーク管理者向けに、Webサーバー（Apache）への配置手順、ネットワーク構成、トラブルシューティングをまとめた技術仕様書です。

---

## 1. システム構成 & 前提要件

* **配信サーバー:** Apache HTTP Server（2.4系推奨、Windows / Linux / macOS いずれも可）
* **サーバーサイド処理:** **一切不要**（PHP, Python, Node.js 等の常駐プロセスやバックエンドスクリプトは使用しません）。純粋な静的ファイル（HTML, CSS, JS）の配信のみです。
* **クライアント要件:** iPad（iOS / iPadOS 14以降推奨、Safariブラウザ）
* **依存ライブラリ（すべてローカル同梱済み）:**
  * `three.min.js` (Three.js r128 / WebGL 3D描画)
  * `peerjs.min.js` (PeerJS 1.5.4 / WebRTC DataChannel通信)
  * `city_gen.js` (決定論的PRNG ＆ 動的ゴール管理エンジン)
  * `webrtc_sync.js` (P2P通信マネージャー)

## 2. サーバー配置（デプロイ）手順

### ステップ 1: ファイルの配置
公開フォルダ（`dist/` または `htdocs/`）の中身を、Apache の公開ドキュメントルート、またはサブディレクトリに配置します。

```text
/var/www/html/whereisOO/dist/  (Linuxの場合)
C:\xampp\htdocs\whereisOO\dist\ (Windows XAMPPの場合)
├── index.html
├── map.html
├── town.html
├── css/
│   └── style.css
├── js/
│   ├── three.min.js
│   ├── peerjs.min.js
│   ├── city_gen.js
│   └── webrtc_sync.js
├── manual/
│   ├── 01_概要・授業指導案向け説明資料.md
│   ├── 02_授業実施マニュアル_教員用.md
│   ├── 03_かんたん操作ガイド_児童生徒用.md
│   └── 04_システム設置・運用手順書_技術担当用.md
└── update_log/
    └── UPDATE_LOG.md
```

### ステップ 2: Apache MIMEタイプの確認
`.js` ファイルが `application/javascript`、`.css` が `text/css` として配信されることを確認します（通常デフォルト設定で問題ありません）。

### ステップ 3: アクセスURLの確認
サーバーのローカルIPアドレス（例: `192.168.1.100`）を確認し、ブラウザからアクセスします：
* URL例: `http://192.168.1.100/whereisOO/dist/`
  （※フォルダ名が半角英数字のため、URL直接入力やQRコード作成時にも文字化けしません）

## 3. ネットワーク構成 & 通信モードの選択

本システムは、学校のセキュリティポリシーや回線状況に応じて2つの運用形態を選択できます。

```mermaid
flowchart LR
    subgraph PatternA["形態A: リアルタイム連携 (WebRTC)"]
        iPadB["iPad B (Explorer)"] -->|CHOOSE_GOAL (目的地決定)| iPadA["iPad A (Navigator)"]
        iPadB <-->|リアルタイム位置・ゴール同期| iPadA
        iPadA <-->|シグナリングのみ| SignalingServer["PeerJS Cloud (443)"]
        iPadB <-->|シグナリングのみ| SignalingServer
    end

    subgraph PatternB["形態B: 完全オフライン・シード方式"]
        Server["校内Apacheサーバー"] -.->|静的HTML配信のみ| iPad1["iPad A"]
        Server -.->|静的HTML配信のみ| iPad2["iPad B"]
        iPad1 -.->|通信一切不要<br>乱数シードのみ一致| iPad2
    end
```

### 形態A: リアルタイム連携モード (WebRTC)
* **概要:** 
  * iPad Bでランダム決定された目的地が、WebRTCメッセージ `{ type: 'CHOOSE_GOAL' }` でiPad Aへ自動送信されます。
  * iPad Bの歩行と向きが、iPad Aの地図上にリアルタイム反映されます。
* **ネットワーク要件:**
  * 初期ペアリング時（シグナリング時）のみ、`0.peerjs.com:443 (HTTPS/WSS)` へのアウトバウンド通信が必要です。
  * 端末間のデータ通信（DataChannel）は、同一LAN内であれば直接P2P通信が行われます。

### 形態B: 完全オフライン・シード共有モード (No Network)
* **概要:** 外部インターネットとの通信を完全に遮断した環境でも動作します。
* **ネットワーク要件:**
  * Apache Webサーバーからの静的HTTP通信（ポート80または443）のみ。外部接続は一切不要。
  * iPad B側でシード値に基づき目的地が表示され、口頭で「Where is the hospital?」と質問します。iPad A側は地図上の建物を指でタップしてターゲットマークできます。
* **運用方法:**
  * 先生が机番号（例: `01`, `02`, `03`...）を指定し、生徒がその数字を入力して開始します。

## 4. iPad Safari 最適化 & ホーム画面追加手順

児童生徒が誤ってタブを閉じたり、アドレスバーを触ってしまわないよう、**「ホーム画面に追加」** してWebクリップ化（全画面表示）することをおすすめします。

1. iPadのSafariで `http://[サーバーIP]/whereisOO/dist/` を開きます。
2. 画面右上の **「共有ボタン（四角から上矢印のアイコン）」** をタップします。
3. メニューから **「ホーム画面に追加」** を選択します。
4. 名前を「英語道案内」などとして「追加」をタップします。
5. ホーム画面に専用アプリアイコンが作成され、全画面で起動できるようになります。

## 5. パラメータのカスタマイズ（高度な設定）

街の広さやセルのサイズを変更したい場合は、`js/city_gen.js` 内の以下の定数を調整できます。

| 定数名 | デフォルト値 | 説明 |
| :--- | :---: | :--- |
| `CELL_SIZE` | `4.0` | 1セルの実寸（メートル）。歩幅やブロックのスケール感です。 |
| `BLOCKS_X` | `4` | 横方向の街区（ブロック）数。 |
| `BLOCKS_Z` | `4` | 縦方向の街区（ブロック）数。 |
| `BLOCK_CELL_SIZE` | `3` | 各街区の一辺のセル数（3×3セル）。 |
