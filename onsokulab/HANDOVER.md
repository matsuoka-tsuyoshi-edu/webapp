# HANDOVER.md - 中学校理科「音の伝わり方と速さ」探究教材Webアプリ（音速ラボ）開発引き継ぎ書

## 1. プロジェクト概要
中学校第1学年理科「音による現象（音の伝わり方・速さ）」の授業において、**「屋外・教室でのリアルな音速実測」**と**「条件（物質・気温）を変えた仮想実験」**の2つの学習活動を1つのアプリで完結させる探究教材Webアプリケーション（アプリ名：**音速ラボ / ONSOKU LAB**）を開発する。

### 開発ステータス（2026-11-20 更新）
* **プロトタイプ（Ver 1.0.0）構築完了・動作確認済み**
* 外部CDNに依存しない純粋な静的構成（HTML / CSS / Vanilla JS + Web Audio API + HTML5 Canvas）で構築しており、GitHub Pages（HTTPS環境）へそのまま配置して動作する。

## 2. ターゲット環境・iPad Safari 最適化要件

* **実行対象:** iPad 横向き・Safari アプリ上での動作を第一ターゲット（Windows / Chromebook / Edge / Chrome でも動作可能）。
* **画面設計（Safari アドレスバー・タブバー考慮）:**
  * `100dvh` ベース＋ `viewport-fit=cover` ＋ `env(safe-area-inset-*)` を使用し、Safari の上下バーが表示された状態でも画面全体（縦スクロールなし）に収まるよう設計（`1024×640` で検証済み）。
* **操作誤動作防止（タブレット向けガード）:**
  * ピンチイン／ピンチアウト（`gesturestart` / `gesturechange` / `gestureend` およびマルチタッチ）を無効化。
  * ダブルタップ拡大および画面全体のドラッグスクロールを無効化（スライダー操作 `input[type="range"]` と履歴テーブル内部の縦スクロールのみ許可）。
* **縦向き警告オーバーレイ:**
  * 画面が縦向き（`window.innerHeight > window.innerWidth` または `@media (orientation: portrait)`）になると、画面全体をグレーアウトし「タブレットを『横向き』にしてください」の案内を表示して操作をブロックする。
* **キャッシュ非生成・毎回キャッシュクリア:**
  * `index.html` の `<meta http-equiv="Cache-Control" ...>` によるキャッシュ抑止。
  * ページ読み込み時に Service Worker 解除・`window.caches` 全削除・`sessionStorage.clear()` を実行し、CSS/JS ファイルは `?v=<timestamp>` 付きで毎回最新を読み込む。
  * Safari の bfcache 復帰時（`pageshow` の `event.persisted`）には自動リロードする。

## 3. ファイル構成・配布パッケージ（`dist/`）

```text
onsokulab/
├── index.html                  # アプリ本体（キャッシュクリア・縦向き警告・3画面SPA）
├── css/
│   └── style.css               # iPad横向き最適化レイアウト（ゼロスクロール設計）
├── js/
│   ├── audio.js                # Web Audio API（レース効果音・ハンターマイク入力監視）
│   ├── hunter.js               # モード1：音速ハンター（実測ツール）
│   ├── race.js                 # モード2：音速レース（物理計算・Canvas粒子アニメーション）
│   └── app.js                  # 画面遷移・縦向きガード・ピンチ/スクロール抑止
├── HANDOVER.md                 # 本引き継ぎ書
├── UPDATE_LOG.md               # アップデートログ（原本）
└── dist/                       # GitHub Pages等への配布用パッケージ一式
    ├── index.html
    ├── css/style.css
    ├── js/{audio,hunter,race,app}.js
    ├── update-log/UPDATE_LOG.md
    └── manual/MANUAL.md        # PowerPoint/Word落とし込み対応マニュアル
```

* **GitHub Pages への反映方法:**
  * ルート一式を公開設定にするか、`dist/` の中身（`index.html`, `css/`, `js/` 等）を公開ディレクトリにアップロードすればビルド不要でそのまま動作する（ソース更新時は `dist/` へ同期すること）。

## 4. 各画面・機能仕様（実装済み内容）

### A. トップメニュー画面（`#view-home`）
* アプリタイトル「音速ラボ 〜音の速さと伝わり方の探究〜」とバージョン表示。
* 2択の大型カードボタン：
  * **【実測】音速ハンター**（`#btn-go-hunter`）
  * **【実験】音速レース**（`#btn-go-race`）
* 公式ヒント：`音の速さ (m/s) ＝ 進んだ距離 (m) ÷ かかった時間 (秒)`

### B. モード1：音速ハンター（`#view-hunter` / `js/hunter.js`）
* **距離設定:** `10m〜500m`（1m刻み、初期値 `100m`）。スライダー、数値直接入力、`−`/`＋` 微調整ボタン、プリセット（`50m / 100m / 150m / 200m`）。
* **計測モード切替:**
  * `👆 手動ストップ`
  * `🎤 マイク自動ストップ`（`AnalyserNode` によるリアルタイム音量メーター＋感度スライダー＋タップ音誤検知防止の `55ms` デバウンス）。
* **2ステップ超大型ボタン（`pointerdown` で遅延なく即反応）:**
  * 待機中：`🚩 光が見えた！（スタート）`
  * 計測中：`🔊 音が聞こえた！（ストップ）` ＋ `✕ やり直す` ボタン
  * `performance.now()` による `0.001秒` 単位のリアルタイム表示。
* **結果・考察・履歴:**
  * かかった時間（秒）と計算された音の速さ（`約 〇〇〇.〇 m/s`）、計算式表示。
  * 折りたたみ式「参考データ」：気温（`-10℃〜40℃`、初期値 `15℃`）に基づく理論値（`331.5 + 0.6 × 気温`）と誤差表示。
  * 直近5回の記録テーブル（個別行削除 `✕`・全削除可）および平均音速の自動算出。

### C. モード2：音速レース（`#view-race` / `js/race.js`）
* **共通コース設定バー:**
  * コース距離：`100m` / `500m` / `1000m` / `3000m`
  * 再生スピード：`等倍（リアル）` / `1/10倍 スロー` / `1/50倍 スロー`
  * `▶ 一斉スタート！` / `↺ リセット` / 経過時間（リアル秒）表示 / ヘッダーに `🔊 音 ON / 🔇 消音中` トグル。
* **比較レーン（上下2段：レーン1・レーン2）:**
  * **媒質（物質）:**
    * `宇宙（真空）`: `0 m/s`（気温スライダー無効化、粒なし、「伝わらない」表示）
    * `空気（気体）`: `331.5 + 0.6 × 気温(℃)` m/s
    * `水（液体）`: `1480 + 2.5 × (気温 - 20)` m/s
    * `鉄（固体）`: 約 `5130 m/s`
  * **気温スライダー:** `-10℃ 〜 +40℃`（初期値 `15℃`、1℃刻み）。
  * **Canvas アニメーション:** 物質ごとの粒子配置（鉄＝規則的格子、水＝やや密、空気＝まばら＆気温で熱運動速度変化、宇宙＝無粒子）と縦波（疎密波）の伝達描画。右端の耳アイコン到達時に Web Audio API でレーン別に音程を変えた効果音を再生し、到達タイムと順位（`🏆 1位！`）を表示。

## 5. 引き継ぎ・今後の拡張候補（次期フェーズ向け）

1. **iPad 実機 Safari での屋外フィールドテスト:**
   * 校庭や体育館で実際のピストル／拍子木を用い、マイク自動ストップのデフォルト感度（現在 `55`）やデバウンス時間（`55ms`）の微調整を検討する。
   * iPad のサイレントスイッチON時の Web Audio API の挙動や、屋外の日光下での視認性を実機確認する。
2. **追加機能のアイデア（必要に応じて）:**
   * ワークシート提出用に、音速ハンターの結果表や音速レースの結果をスクリーンショットしやすい「まとめ表示」やCSV/テキストコピー機能。
   * 他の物質（ヘリウム、二酸化炭素、木、ガラスなど）の追加。
3. **メンテナンス上の注意:**
   * 機能追加・修正時は、必ずルート側のファイルを編集したうえで `dist/` フォルダへ同期し、`UPDATE_LOG.md`（ルート側と `dist/update-log/UPDATE_LOG.md`）および `dist/manual/MANUAL.md` を更新すること。
