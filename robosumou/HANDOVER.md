## 1. プロジェクト概要

「ロボ相撲 (ROBO SUMO) - CYBER STAGE」は、教育現場（小・中・高等学校およびプログラミング教室等）において、児童生徒が自律型ロボットのアルゴリズムを視覚的かつ直感的に組み立て、物理シミュレーションによる相撲バトルを通じてプログラミング的思考を学ぶためのWebアプリケーションです。

v2.3.0では、子どもたちがロボットの動きや勝敗の理由をしっかり観察できるよう、**3本勝負（2本先取制／1本勝負切替可）・制限時間設定（10〜30秒）・時間切れエナジー判定勝ち＆サドンデス（収縮リング）・目で追える相撲ペース＆決め手スローモーション演出**を生徒・先生両画面に実装しました。

### 基本方針
- **ゼロディペンデンシー（単一HTML完結）**:
  外部フレームワークや外部オーディオファイルを使用せず、標準のHTML5/CSS3/JavaScript（ES6+）のみで実装。通信部にはオープンなWebRTC P2Pライブラリ（PeerJS）を採用。
- **デュアル・ウィン（2大勝利条件）の採用**:
  相撲の「寄り切り・押し出し（リングアウト）」に加え、サイバー相撲としての「エナジー切れによるK.O.（機能停止・電源喪失）」という2つの決着方式を両立。
- **WebRTCによるサーバーレス教室連携**:
  先生の画面に表示される4桁コードを入力するだけで、教室内LAN環境等においてサーバー構築不要で機体データをP2P送受信。
- **既存UI/UXとデータの100%後方互換性維持**:
  保存データフォーマットおよびLocalStorageキー（`robosumou_my_robots`）は完全互換。

## 4. 内部仕様とアルゴリズムの詳細

### 4.1 エナジー & ダメージシステム
- 各プレイヤーは `energy` と `maxEnergy` を保有（初期値：normal=100, speed=80, power=130, technical=90）。
- **飛び道具直撃ダメージ**:
  - `target.isShielding > 0`: ダメージ0（「GUARD!」表示、シールド火花）
  - 通常時: `20` ダメージ。ノックバック発生。
- **衝突ダメージ**:
  - 毎フレームではなく、新たに衝突した瞬間（`!wasColliding`）に発生。
  - 通常衝突: `8` ダメージ
  - ダッシュ突撃衝突: `25` ダメージ
  - 相手がシールド展開中: ダメージ0（「GUARD!」表示）
- **ダメージポップアップ**: `createDamageText(x, y, text, color)` により、Canvas上に上方向へ浮遊しながらフェードアウトする数値を描画。

### 4.2 シールドシステム (`shield`)
- ブロック実行時、`player.isShielding = 90;`（約1.5秒間持続）を設定。
- シールド展開中は、機体周囲に半径 `radius + 15` のネオンブルー発光円を描画。
- 被弾および激突ダメージを完全無効化。

### 4.3 K.O.判定と大爆発エフェクト (`checkKo`, `createKoExplosion`)
- `player.energy <= 0` に達した瞬間：
  1. `player.energy = 0` に固定。
  2. `createKoExplosion(x, y)`: 2重の衝撃波リング（`shockwaves`）と45個の高速爆発パーティクルを生成。
  3. `sound.playKoExplosion()`: 重低音オシレーター合成による爆発音。
  4. `screenShake = 24`: Canvasの描画原点を振動させる。
  5. 勝敗宣告（`endBattle`）。

### 4.4 ピンチ状態演出
- `energy / maxEnergy <= 0.35`（エナジー35%以下）の場合：
  - HUDエナジーバーが赤色（`#ff0055`）に変化。
  - 機体頭上のミニHPバーも赤色に変化。
  - 毎フレーム30%の確率で機体から黒煙パーティクルを放出、さらに電気火花スパークを散乱。

## 6. 保守・拡張時のガイドライン

### 6.1 新しいブロックを追加する場合
1. `#toolbox` 内にブロックマークアップを追加。
2. `executeRobotBrain` に実行処理を追加（即時処理または `player.currentAction` の設定）。
3. 持続系アクションの場合は `progressAction` にステップ更新処理を追加。
4. シリアライザ（`serializeProgram` / `buildWorkspace`）は自動対応。

### 6.2 注意点
- オフライン動作と学校セキュリティを保証するため、外部ライブラリや外部音声・画像ファイルへの依存は絶対に追加しないでください。
- スクリプト全体が単一 `<script>` タグ内に記述されているため、同一ブロックスコープ内での重複宣言（`const` / `let`）や構文エラーが発生すると、JavaScriptエンジンがスクリプト全体の評価を停止し、全画面遷移や初期化処理が沈黙します。修正時は必ず構文整合性を検証してください。

## 7. 先生用トーナメントシステム (`sensei.html`) の仕様

### 7.1 通信仕様 (WebRTC / PeerJS)
- **ライブラリ**: `peerjs@1.5.2` (CDN経由)
- **STUNサーバー**: Google Public STUN (`stun:stun.l.google.com:19302` 等3系統)
- **プレフィックス**: `robosumo-`
- **Peer ID生成**:
  - 先生側: `const fullPeerId = 'robosumo-' + 4桁コード;`（例: `robosumo-7842`）
  - 生徒側: 先生の画面に表示された4桁コード（例: `7842`）を入力し、`robosumo-7842` へP2P接続。
  - これにより、同一ネットワークやPeerJS公開ブローカー上で他アプリ（`pgmsakana`等）とコードが競合することを完全に防止。
- **ペイロードフォーマット**:
  ```json
  {
    "name": "マイロボ1",
    "type": "normal",
    "program": [ ... ],
    "sentAt": 1731737400000
  }
  ```

### 7.2 画面フェーズ遷移ステートマシン
1. **受付フェーズ (`reception`)**:
   - 4桁エントリーコード表示、リアルタイムエントリー一覧表示。
   - **試合ルール設定**: ツールバー内で「🏆 3本勝負（標準）/ ⚔️ 1本勝負」と「⏱️ 制限時間（10〜30秒）」を事前設定可能。
   - 人数に応じて4枠、8枠、16枠のツリーを自動構築。
   - 不足分は「🤖 ダミー4体追加」で自動補完可能。
   - 先生によるドラッグ＆ドロップでのシード・組み合わせ編集。
2. **試合会場フェーズ (`battle`)**:
   - **3本勝負・星取り進行**: 2本先取（または1本勝負）を星取りランプ（★）で表示。「はっけよい…のこった！」演出→じっくり見える相撲物理→決着スローモーションカットイン→次本へ自動移行。時間切れ時は残エナジー判定、同点は収縮リング付きサドンデスで完全決着。
   - **スクロール完全排除＆大型土俵設計**: 試合会場フェーズ中はヘッダーを隠し、ラウンドバナー・対戦HUD・大迫力の大型土俵（`min(490px, calc(100dvh - 210px))`）・操作ボタン（試合開始・リプレイ・次へ）がスクロールなしで1画面に収まり、下部ボタンも28pxの安全余白で絶対に見切れない。
   - **生徒画面と完全同期したタンク車体描画**: 左右のキャタピラ（履帯）、主砲バレル＆マズル、旋回ターレット、衝突時に赤色点滅する照準センサーアイ、ダッシュ時のブースト噴射を大画面用に精密描画。
   - **80px上方引き上げ実況ログ**: サイドバーのリアルタイム実況ログを高さ240px以上とし、白熱のテキスト中継をたっぷり表示。
   - 右上ミニトーナメント表で進行度をリアルタイムハイライト。
   - 操作: 「試合開始 / 一時停止」「リプレイ」「次の試合へ進む」。
   - 勝者は自動的に次ラウンドの対戦枠へ進出。
3. **専用表彰式フェーズ (`ceremony`)**:
   - 決勝戦終了後に専用の表彰台ステージへ自動遷移。
   - 3位 ➔ 2位 ➔ 1位の順に、専用ファンファーレ＆スポットライト演出でキャラクターが登場。
   - 表彰台の上で各キャラクターがリズムに合わせてピョンピョン跳ねる祝賀アニメーション。
   - 全画面紙吹雪エフェクト。
   - タイトル「🏆 VICTORY CEREMONY 🏆」右側のトロフィー横に配置された「🔄 リセット」ボタンで、ワンタップで次回大会の受付画面へ復帰可能。
